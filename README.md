# AgentReadable

**AI agents now read your website for your customers. We measure how accurately your real pages get through to each AI reader, by layout and by model, and show which layout survives even the weakest model.**

Built solo (GitHub @TaeWoo1) at Daytona HackSprint Seoul (2026-10-18) with **Daytona** sandboxes and **Nosana** GPUs.

## The problem

A customer asks an AI agent: *"I need an RTX 4090 that won't be interrupted. How much per hour?"*
The agent opens the vendor's pricing page and answers. On the real `daytona.io/pricing` page (captured 2026-10-18 15:35 KST, `data/raw/`), the GPU table shows the **Preemptible** tab by default ($0.57/h for the RTX 4090). The **On-demand** price ($0.99/h) sits in a hidden tab panel. An agent that sees only the visible text can quote the preemptible price as if it were the guaranteed price.

We don't measure AI *search visibility* (that's what GEO tools do). We measure **comprehension accuracy**: given the page, does the AI reader get the facts right?

## How it works

```
real page ──► gold answer key (data/gold)          ┌─ Nosana GPU: Qwen 3.5 9B
     │                                              ├─ Nosana GPU: gpt-oss 20B
     └─► layouts A / B / C (src/gen_sites.py)       ├─ Nosana GPU: Gemma 4 26B
              │                                     └─ Anthropic API: Claude
              ▼                                               │
   Daytona sandboxes (one per layout × worker)   ◄── open_page tool calls
   each serves its layout on localhost:8000      (exec'd inside the sandbox)
              │
              ▼
   results/runs.jsonl ─► src/grade.py (code, no LLM judge) ─► src/report.py ─► results/dashboard.html
```

- **Layouts** (facts identical, generated from the same gold JSON):
  - **A_original**: mirror of the real page structure: tabbed GPU prices with the On-demand panel `hidden`, and the "*first 5 GiB free" storage footnote.
  - **B_explicit**: one GPU table with both columns visible, labelled "Preemptible (may be interrupted)" and "On-demand (not interrupted)". The storage free tier sits next to the price.
  - **C_faq_structured**: B plus a plain-text FAQ and JSON-LD `Offer` / `UnitPriceSpecification`.
  - **NOPAGE**: no tools at all (memory-only control).
- **Reader agent** (`src/agent.py`): same system prompt and the single tool `open_page(path)` for every model. Temperature 0, at most 6 tool steps. It returns strict JSON with the answer fields, `evidence_quote`, and `not_found`.
- **Reader modes** (`src/sandbox_extract.py`, runs inside the sandbox):
  - `html_text`: all HTML text, including hidden panels (like a crawler).
  - `visible_text`: hidden elements dropped. This is a *static approximation* of a browser view, not a real browser render.
  - `rendered_text` (`src/sandbox_render.py`, q1 only): **real Chromium inside the Daytona sandbox** via Playwright.
    - `open_page` returns `page.inner_text("body")`. An extra `click(text)` tool clicks the first element matching the text.
    - Every step saves a full-page screenshot to `results/frames/<run_id>/step_N.png`.
    - Each call is a fresh browser: the run's click history is replayed, so calls stay stateless and reproducible.
    - Layout A has the same working tab script as the real page. `html_text` and `visible_text` drop `<script>`, so their outputs are byte-identical to before the script was added.
- **Daytona**: every page fetch and text extraction runs inside an isolated, ephemeral Daytona sandbox, with a fresh process per tool call and no shared cookies or state. Fan-out uses several sandboxes per layout in parallel.
- **Nosana**: three open-weight reader models are served with Ollama on Nosana GPUs (RTX 3090 / 4090).

## Metrics

All metrics are graded by code against the gold key:

- **Field accuracy**: share of answer fields that match gold.
- Each run is counted as **correct / not_found / wrong / invalid**.
- **Wrong** means a confident wrong value, which is worse than not_found.
- **Evidence reach**: did the gold string appear in the tool outputs?
- **Headline: worst-model accuracy per layout.**

## Results

All numbers come from `results/summary.json`, generated by `src/grade.py` from `results/runs.jsonl`, `results/runs_visible.jsonl`, `results/runs_rendered.jsonl` (v1) `results/runs_rendered_v2.jsonl` (v2, n=3) and `results/runs_rendered_v2_n10.jsonl` (v2 headline).

- 4 reader models (Qwen 3.5 9B, gpt-oss 20B, Gemma 4 26B on Nosana; Claude `claude-sonnet-4-5` via the API).

**Findings** (in these runs, n is small):

1. **When the reader only sees what's visible (visible_text, static approximation), the original tabbed layout fails q1 for every model: 0/12.**
   - gpt-oss 20B answered $0.57 labelled "on_demand" in 3/3 runs (the preemptible price passed off as the guaranteed price).
   - Qwen gave a wrong value in 1/3 runs.
   - Claude and Gemma answered "not found" (3/3 each).
2. **The same facts in an explicit layout fix it.** The worst-model q1 rate rises from 0% (A) to 100% (C) in visible_text mode.
3. **A crawler-style reader (html_text) sees the hidden On-demand panel**, and every model gets q1 right on A (12/12). The failure depends on *how* the agent reads the page.
4. **With a real browser and a click tool, A depends on whether the agent explores.** v1 A: 8/12. v2 headline A (styled like the real page): 21/33, correct given clicked 21/23, correct given no click 0/10, and all no-click runs were gpt-oss confidently answering $0.57. C: v1 12/12, v2 headline 20/20. An explicit layout removes the dependence on agent behaviour.
5. **Memory isn't enough.** NOPAGE answers are mostly "not found" (field accuracy 0–20% per model), so readers do depend on the page.
6. **Ambiguous wording shows up as model disagreement.** On q5, some runs answered $0.1362/vCPU/h (= vCPU $0.0504 + Windows $0.0858), reading the Windows price as a surcharge. The page doesn't say which reading is right, so **q5 gold is unverified** (graded at face value, $0.0858).
7. **Qwen 3.5 9B is the weakest reader overall.** Most of its failures are formatting, not comprehension: malformed JSON (an unescaped quote inside `evidence_quote`), or malformed tool-call XML that the server rejected. They are graded strictly as `invalid`.

## Judging criteria

### Completeness
- End-to-end pipeline: real page → gold (`data/gold/`) → layouts (`src/gen_sites.py`) → Daytona sandboxes (`src/daytona_pool.py`) → reader agents (`src/agent.py`) → code grader (`src/grade.py`) → dashboard (`results/dashboard.html`) and deck (`deck/deck.pdf`).
- 521 graded runs committed in `results/runs*.jsonl`, with `results/summary.json` and 97 replay screenshots in `results/frames/`. Every number here can be checked without rerunning.
- One-command live demo: `./demo.sh` (~20 s).

### Innovation
- GEO/AEO tools measure *visibility* (is my brand mentioned?). We measure *comprehension accuracy* (does the agent get my facts right?), per layout × reader model × reading mode, with a worst-model metric.
- The reading mode is an experimental dimension: crawler text vs static visible text vs a real browser with a click tool. The same page passes in one mode (A html_text 12/12) and fails in another (A visible_text 0/12).

### Real-Life Problem Solving
- Real, public page (`daytona.io/pricing`, captured in `data/raw/`). The default tab shows the preemptible price, and agents quoted it as the "won't be interrupted" price: gpt-oss 20B answered $0.57 "on_demand" in 3/3 visible_text runs and in 10/10 rendered_text v2 headline runs.
- Fix shown on the same facts: layout C (labelled columns + FAQ + JSON-LD) is 12/12 for q1 in every reading mode, including both real-browser runs.

### Sponsored Product Usage
- **Daytona**: 24 ephemeral sandboxes across all batches, each serving one layout on localhost:8000. All 624 reader tool calls (`open_page`, `click`) ran inside the sandboxes. **Headless Chromium (Playwright) runs inside the sandbox** for rendered_text, with screenshots per step. Fan-out: several sandboxes per layout in parallel (each rendered batch: 24 runs on 6 sandboxes, 87 s for v1 and 88 s for v2).
- **Nosana**: 3 open-weight reader models (Qwen 3.5 9B on an RTX 3090; gpt-oss 20B and Gemma 4 26B on RTX 4090s) served with Ollama on decentralized GPUs. the 3 Nosana models' graded runs were served from Nosana.

## Limitations (read before quoting numbers)

- Small n (3 reps per cell, temperature 0). Read the results as "in these runs", not as proof.
- One page (Daytona pricing) and one site mirror. Layout A is a simplified mirror of the real page, not the live page.
- `visible_text` is a static approximation (it drops `hidden` / `display:none`), not a real browser render.
- `rendered_text` (real Chromium) was run for q1 only, on layouts A and C, with n=3 per model, on two site versions: v1 plain mirror and v2 styled like the real page. Both are our re-creations served from Daytona sandboxes, not the live site. v2 matches the look (dark theme, pill toggle) but uses no real fonts, images or Framer markup.
- Field accuracy gives partial credit. For example, on q1 an answer with `pricing_type: on_demand` but no price still gets 1 of 2 fields. The per-question "fully correct" counts are the stricter view.
- OpenAI was configured but excluded: the key had no credits (HTTP 429). Those runs are listed under `excluded_infra_errors`.
- Gold ambiguities: whether "first 5 GiB free" applies per sandbox or per org is not stated (both readings fall inside the q2 tolerance), and "preemptible" is not defined on the page.
- We do not claim any AI search ranking or citation effect.

## Run it

```bash
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env    # DAYTONA_API_KEY, NOSANA_*_BASE_URL/MODEL, ANTHROPIC_API_KEY, (OPENAI_API_KEY)
.venv/bin/python src/gen_sites.py
.venv/bin/python src/run_matrix.py --mode html_text    --out results/runs.jsonl
.venv/bin/python src/run_matrix.py --mode visible_text --layouts A_original,B_explicit,C_faq_structured --out results/runs_visible.jsonl
.venv/bin/python src/run_matrix.py --mode rendered_text --models claude,gpt-oss-20b,qwen3.5-9b,gemma4-26b --layouts A_original,C_faq_structured --questions q1 --workers 3 --out results/runs_rendered.jsonl
.venv/bin/python src/run_matrix.py --mode rendered_text_v2 --models claude,gpt-oss-20b,qwen3.5-9b,gemma4-26b --layouts A_original,C_faq_structured --questions q1 --workers 3 --out results/runs_rendered_v2.jsonl
R="results/runs.jsonl results/runs_visible.jsonl results/runs_rendered.jsonl results/runs_rendered_v2.jsonl"
.venv/bin/python src/grade.py  $=R   # zsh; in bash use $R
.venv/bin/python src/report.py $=R   # -> results/dashboard.html
.venv/bin/python src/deck.py   $=R   # -> deck/deck.pdf
```

## Repo

- `data/raw/`: the real page as captured.
- `data/gold/`: facts, questions, and gold answers.
- `sites/`: layouts A, B and C (v1, plain mirror HTML).
- `sites_v2/`: layouts A and C restyled like the real page (v2, rendered_text_v2 only).
- `src/`: agent, Daytona pool, runner, grader and report.
- `results/`: raw runs (full tool transcripts), graded runs, summary, dashboard.
- `LOG.md`: timestamped decisions and failures.
